# AGENTS.md

This file (`AGENTS.md`) is the canonical agent configuration. `CLAUDE.md` is a
symlink to this file.

Context for AI coding agents working on this repository.

## What this is

The root user site for GitHub Pages, published at <https://lsimons.github.io/>.
A small landing page listing my open source pet projects, built with Astro
Starlight (bun). Because it is the *user* site it deploys at the domain root -
there is no `base` path (project sites like agent-engineer-course and caseum set
their own).

## Layout

- `docs/` - Astro Starlight site. Landing page:
  `docs/src/content/docs/index.mdx` (a `template: splash` page). Config:
  `docs/astro.config.mjs`.
- The landing page renders, in order: the intro (`docs/src/intro.md`), a
  hand-curated Featured section of clickable cards, a "My stuff" list from the
  auto-generated `docs/src/data/repos.json`, a "Work stuff" list of org links,
  and an "Old stuff" list. `repos.json` is generated by `mise run docs-repos` (see
  below) and committed so builds need no network. `intro.md` was seeded from my
  profile README but is now hand-curated - do NOT regenerate it, and note that
  nothing does: `docs/scripts/refresh-repos.mjs` writes `repos.json` only.
- The header menu (Home/Blog/GitHub/LinkedIn, mirroring leosimons.com) is
  `docs/src/components/Nav.astro`, wired via `components.SocialIcons` in
  `astro.config.mjs`. custom.css keeps it visible on mobile (Starlight would
  otherwise hide it since there is no sidebar/mobile menu).
- The favicon (`docs/public/favicon.png` + `apple-touch-icon.png`) was
  generated from `docs/src/assets/profile.png` with `sips`. The exact
  invocation was never recorded; there is no task for it. This used to say
  "(see README)", but the README has never described it.
- `.mise.toml` - every tool pinned to an exact version (bun, prek, lychee,
  gitleaks, zizmor, actionlint, shellcheck), plus the tasks below. Run
  `mise install` first. See `mise tasks` for the full list.
  `mise run docs-repos` re-scans GitHub (needs authenticated `gh`) and rewrites
  `docs/src/data/repos.json` only - public, non-fork, non-archived repos, minus
  an exclude list. It does not touch `intro.md`.
- Dev server: `mise run docs-dev` -> <http://localhost:4321/>. Astro 7's
  `astro dev` daemonizes: manage with `astro dev stop|status|logs`.

## Rules

- **No `base` path.** This is the user site at the domain root. Do not copy the
  rehype base-link plugin from the project sites.
- `.mdx` landing page: mdformat and markdownlint mangle JSX, so the prek hooks
  exclude `.mdx`. Keep new content pages as `.md` where possible.
- Formatting is mdformat style; the pre-commit hook enforces it for `.md`.

## Tooling / process

- Git hooks via prek (`prek install -t pre-commit -t commit-msg` once per
  clone): mdformat, markdownlint, lychee (link check), gitleaks, commitlint.
  `mise run lint` runs the nine `pre-commit`-staged hooks over every file
  (skipping the networked lychee hook) plus `actionlint`, so CI catches what an
  uninstalled hook would have missed. **commitlint is not among them**: it is
  `commit-msg`-staged, so an uninstalled commit-msg hook is still not caught by
  CI.
- **Conventional commits are enforced** (`docs:`, `fix:`, `ci:`, `build:`,
  `feat:` ...). Also add `Assisted-by: <Agent>:<model>` trailer per user
  convention.
- **`mise run ci` is the gate**: install (frozen lockfile), lint, Astro check,
  build. Run it before pushing. `.github/workflows/ci.yml` runs the same four
  steps in the same order - keep the two lists in sync.
- `mise run audit` runs the same zizmor audit as the workflow's zizmor job, at
  the same pinned version, but **deliberately one notch stricter**: it adds
  `--strict-collection`, which fails rather than warns on syntax and schema
  errors in collected inputs. The action does not set it. Local ≥ CI is the
  safe direction. It also needs an authenticated `gh` and refuses to run
  without one, rather than silently falling back to a weaker offline audit.
- Deploy (`deploy.yml`) publishes `docs/dist` to GitHub Pages on push to main.
  The Pages source must be "GitHub Actions" (not "Deploy from a branch").
  **Deployment is load-bearing: do not break this workflow.**
- Dependabot is active (bun + actions, weekly, 7-day cooldown); typescript is
  held to 6.x - keep the ignore rule. It *is* a `version-update:semver-major`
  ignore, but scoped to `typescript` alone and for a checked reason:
  `@astrojs/check` declares `peerDependencies.typescript = "^5.0.0 || ^6.0.0"`,
  so TypeScript 7 would break the `docs-check` task. Do not generalise it to
  other dependencies - majors are otherwise allowed to flow, with green CI as
  the acceptance signal.
- Verify changes with `mise run ci`. To eyeball the layout, run
  `mise run docs-browser` once (installs Playwright's Chromium), then
  `mise run docs-screenshot out.png` builds, serves, and captures the landing
  page at 1280x800.
- Nothing validates root-relative internal links - see the note in
  `.lychee.toml`.

## Agent skills

### Git remote

Use GitHub, with the `gh` CLI.

### Issue tracker

**None — this repository has GitHub Issues disabled** (`has_issues: false`; so
are Projects, the wiki and Discussions). `gh issue` fails here. Work arrives as
pull requests against `main`, and security reports through the Security tab's
"Report a vulnerability" button. If you are asked to file an issue, say that
you cannot rather than working around it. See
[docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

### Triage labels

needs-triage, needs-info, ready-for-agent, ready-for-human (all `#e6e6fa`).
Labels are shared between issues and PRs, so with issues off they can only be
applied to pull requests. `wontfix` and the other GitHub defaults exist but are
not part of the triage set. See
[docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).
